## 1. Что это за проект

**«Атланты»** — коллекционная карточная игра (жанр card battler в духе Slay the Spire),
которую делают для размещения в мобильном приложении **«Клуб Друзей»** (сеть магазинов СПАР)
в формате веб-вью.

**Идея продукта:** покупатель получает физическую карту с QR (бесплатно при чеке от 1000 ₽
или покупает на кассе), сканирует QR в приложении — карта попадает в его цифровую колоду.
Колодой сражается в дуэлях. Идентификатор игрока — его id в «Клубе Друзей». Колода хранится
на сервере, привязана к id. На старте выдаётся слабая стартовая колода.

**Что сделано на данный момент:** играбельный **веб-прототип** (папка `proto/`) —
с настоящими картами и правилами из оригинальной игры, разложенный по экранам
из схемы в Figma (раздел 13): главный экран, PvE, колоды, редактор, сканирование, профиль.
Бой идёт против скрипта (бота).

**Мультиплеер сейчас выключен** по просьбе заказчика: экран PvP есть, лобби пустое.
Код онлайна никуда не делся (раздел 12), включается обратно одной строкой.

## 4. Правила боя (перенесены из движка оригинальной игры)

Источник правды — код оригинала в `aha-game-client-main/Assets/_SPAR/_Scripts/Runtime/Battle`
(`BattleAPI.cs`, `FighterBehaviour.cs`, `PlayerBehaviour.cs`, `Commands/*`).

- Здоровье **50** (`MAX_HP`), энергия **3** за ход (`MAX_NRG`), рука **5** карт (`HAND_SIZE`).
  (В оригинале старт 90 HP; понизили до 50 для скорости, но настоящие карты бьют сильно —
  бои по 3–7 ходов. Вопрос «вернуть 90» остаётся открытым.)
- **Урон** = базовый + сила атакующего; гасится блоком, остаток в HP.
- **Блок** = базовый + ловкость; сгорает в начале СВОЕГО хода (если нет переноса).
- **Энергия** восстанавливается до максимума каждый ход, не копится (если нет переноса).
- **Сила/ловкость** — постоянные баффы до конца боя (обнуляются только при старте боя).
- **Перенос блока/энергии** (знак `!` в конфиге): остаток переносится на N ходов
  (счётчики `trBlock`/`trNrg`; есть карты на 10 ходов).
- **Дебафф силы/ловкости** (наш выбор, отход от оригинала): действует **1 ход** жертвы,
  потом снятое возвращается. Хранится списком `debuffs:[{stat,amount,wait}]` — у каждого
  свой срок (наложенный позже не продлевает ранний). Нижней границы нет (уходит в минус).
- **Умножение** (знак `*`): ×2/×3 силы/ловкости/блока/энергии. Защита: умножение
  **отрицательного** значения силы/ловкости ничего не делает (иначе была лавина −64).
- **Изгнание** (Disappear): карта после розыгрыша уходит из боя (`exhaust:true`).
- Пустая колода перетасовывается из сброса. Урон никогда не отрицательный.

## 5. Система карт

**84 карты**, параметры взяты из **Unity Remote Config** (ключи `cardsAttack`/`cardsDefend`/
`cardsMagic`), а не из ручной расшифровки. База — `proto/cards.js`.

- **Ключ карты = имя спрайта:** `a2`=Attack2, `d6`=Defend6, `m28`=Magic28. Арт — `img/cards/<ключ>.png`.
- Нумерация набора: атака 1–28, защита 29–56, магия 57–84 (85–100 — карты врагов, не заведены).
- **Улучшенные версии карт** (`cardUpgradedEffects` в конфиге) НЕ используются — только базовые
  (по решению заказчика; каждая карта — один вариант).
- Формат карты: `{ no, type, cost, title, tpl, fx:[...], exhaust? }`.
  `tpl` — человеческий текст (справочно, в UI не показывается).
  Описание в UI генерируется из `fx` функцией `cardDesc()`: компактно, знаками и иконками.
- **Типы эффектов `fx.k`:** `dmg` (урон), `hpFoe` (прямой урон мимо блока), `hpSelf` (себе/лечение),
  `blk`, `str`/`dex`, `strFoe`/`dexFoe`, `mulStr`/`mulDex`/`mulBlk`/`mulNrg`, `nrg`, `draw`,
  `trBlock`/`trNrg` (перенос), `copyHand`/`copySelf`/`copyDeck`.
- **Перевод знаков конфига** (в генераторе): `''`→установить/базовый, `+`/`-`→плюс/минус,
  `*`→умножение, `!`→перенос. targetType Caster/Itself → игрок; ChosenTarget/Enemies/Player → враг.
- **Как пересобрать `cards.js` из конфига:** парсить `data/remote-config.csv`, взять `cardsAttack`/
  `cardsDefend`/`cardsMagic`, поле `cardEffects` (НЕ `cardUpgradedEffects`), маппить по таблице выше.

**Арт карт** нарезан из атласов Unity `Assets/_SPAR/UI/Cards` (`Attack1-24.png`+`.tpsheet` и т.д.).
Внимание: экспорт/нарезка Figma и Unity склеивает картинки с тёмным фоном холста (#1E1E1E) —
прозрачность надо восстанавливать flood-fill; координаты спрайтов в `.tpsheet` считаются от
НИЗА текстуры (`crop(x, H-y-h, x+w, H-y)`).

## 6. Колоды и редактор

- Боевая колода — **20 карт**, максимум **3 копии** одной карты (`MAX_COPIES`, из `cardAddingLimit`).
- **Редактор колод:** 20 слотов (10 в ряд) сверху, ниже все 84 карты (10 в ряд, прокрутка).
  Клик по карте — добавить, по слоту — убрать. Счётчик копий `×N`.
- **Стартовая колода** (`STARTER_DECK` в cards.js) — из `startDeck` конфига, продублирована до 20:
  Копьё×8, Щит×8, Ксифос×2, Гоплон×2. Заведена как обычная редактируемая колода с меткой СТАРТ,
  удалить нельзя. Есть миграция: старая 10-карточная в localStorage дополняется до 20.
- **Пресеты:** Натиск / Оборона / Энергия — засеиваются один раз.
- **Хранение колод — localStorage** (ключ `atlanteans_decks`). НЕ на сервере — на другом
  устройстве колод нет. Есть перенос строкой: кнопки «Скопировать»/«Вставить» (код вида
  `ATL1:Название:9,9,8,...`).
- **Экран выбора:** у каждой колоды кнопки «мне»/«врагу» — можно задать колоды обеим сторонам
  (для отладки). Соперник иначе берёт случайную из сохранённых. Бой при загрузке НЕ стартует —
  только по кнопке «Играть».

## 7. Интерфейс прототипа (что уже сделано)

- Сцена собрана в размерах фрейма Figma (2597.4×1568.8), масштабируется целиком — пропорции
  графики сохранены. Персонажи из исходников с прозрачностью; Афина отражена (`--fx:-1`).
- Розыгрыш карты — перетаскиванием в центр экрана. Ход бота: его карта показывается в центре,
  потом срабатывает эффект.
- **Энергия — цифрой 0–999** в синей «пилюле» (не секторами).
- **Описание карт:** компактное, из `fx`, иконки вместо слов параметров, выравнивание по левому
  краю. Текст 27px **жирный**. **Цифра урона — слева и крупнее в 1.5 раза** («12 урон врагу»).
  Бонус силы/ловкости подсвечивается зелёным (`.buffed`).
- **Индикатор переноса** блока/энергии под характеристиками (иконка + число ходов).
- **Отладочный лог** (кнопка ≡): все действия, эффекты подробно, сводка состояния, спад дебаффов.
- **Просмотр колоды** по клику на стопку: группировка по типу, сортировка по стоимости,
  карты руки помечены.
- **Мобильное:** touch-action для перетаскивания и прокрутки, подгон по высоте экрана,
  просьба повернуть в портрете, полноэкранный режим (кнопка + PWA-манифест).
- **HP-бар** под аватаром, без полупрозрачной подложки.

**Тесты:** `node proto/proto-test.js` — headless-прогон логики (стабит DOM), 49 проверок.
Запускать после любой правки движка. Тестовая партия использует фиксированную агрессивную
колоду (случайные колоды с копиями+переносом энергии могут зациклиться — артефакт жадного бота).

## 12. Онлайн-бой вдвоём (как устроен)

**Схема:** хост считает бой, релей передаёт, гость рисует.

- `relay.js` правил игры НЕ знает. Он держит комнату по 4-значному коду, хранит последний
  снимок состояния от хоста и очередь действий от гостя. Комната живёт 6 часов, лежит
  в памяти процесса (перезапуск сервера обрывает бои). Заодно раздаёт статику репозитория,
  чтобы игра и API были на одном адресе. Порт — `process.env.PORT` (Railway) или 3000.
- **Ключевой приём:** хост отдаёт снимок **уже перевёрнутым** — свои и чужие местами.
  Поэтому у гостя весь существующий рендер (`S.p[0]` — «я») работает без единой правки.
  Переворот в `flip()` в `proto/net.js`.
- Чужая рука и стопки в снимке обезличены (`blind()`): видно только количество карт.
- Гость движок не считает вообще. Он шлёт действия `{t:'play'|'take'|'end'|'again'}`,
  хост применяет их в `applyRemote()` тем же кодом, что и свои ходы (`playBy`).
- Опрос — раз в 800 мс в обе стороны. Снимок шлётся не на каждый `render()`,
  а по флагу «грязно» раз в такт. Пока карту тянут пальцем, снимок не применяется,
  иначе жест обрывается.
- В шапке вместо «ПРОТОТИП ДУЭЛИ» показывается код боя; если соперник не выходил
  на связь больше 10 секунд — «СОПЕРНИК ОФФЛАЙН».

**API релея:** `POST /api/create {deck}` → `{code, token}`; `POST /api/join {code, deck}` →
`{token}`; `POST /api/push {code, token, snap}` (только хост); `POST /api/act {code, token, act}`
(только гость); `GET /api/poll?code&token&ack|rev` — хосту отдаёт колоду гостя и его действия,
гостю — свежий снимок.

**Чего в этом варианте нет:** переподключения (перезагрузил страницу — бой потерян),
защиты от жульничества хоста, колод на сервере, подбора соперника. Оба игрока
по-прежнему видят себя слева как ZEUS — имена бойцов зашиты в вёрстку.

Без `net.js` игра работает как раньше, против бота: в `index.html` лежит заглушка `NET`.

|---|---|---|
| Главный | `menuScreen` | Зевс, логотип, кнопки КОЛОДА / PvP / PvE, аватар в углу |
| PvE выбор колоды | `pveScreen` | список колод с выбором «мне»/«врагу», кнопка ИГРАТЬ |
| PvP лобби | `pvpScreen` | **пусто** — мультиплеер выключен |
| Экран колод | `decksScreen` | список колод, «изменить», «✕», СОЗДАТЬ КОЛОДУ, ОТСКАНИРОВАТЬ КАРТУ |
| Редактор колоды | `deckEditor` | без изменений: 20 слотов, 84 карты, лимит 3 копии |
| Сканирование карты | `scanScreen` | видоискатель; ручного ввода кода НЕТ (см. ниже) |
| Профиль | `profileScreen` | аватар, имя, побед/поражений (в localStorage `atlanteans_profile`) |

Переходы: назад — по `data-back` на стрелке, вперёд — обработчиками кнопок.
Экран боя из потока экранов исключён: он показывается, когда все `.screen` скрыты
(`showScreen(null)`). Выйти в меню можно кнопкой «В МЕНЮ» на экране итога
или иконкой ⌂ в правом верхнем углу — она и кнопка лога ≡ видны только в бою
(класс `body.inmenu` снимает их, пока открыт любой экран).

**Чего в этих экранах НЕТ:**
- камеры и разбора QR (раздел 9, пункт 4). **Ручного ввода кода нет и не будет**:
  карта достаётся только сканированием физической карточки, иначе номера можно
  подобрать перебором. Когда камера появится — распознали QR, нашли ключ карты
  и вызвали `cardScanned(key)`, окно «Карта добавлена» уже готово;
- коллекции карт: «Карта добавлена» ничего не ограничивает, в редакторе по-прежнему
  доступны все 84 карты. Настоящая коллекция — отдельная задача;
- смены аватара: картинка одна, взята из старой игры.

**Как вернуть мультиплеер:** раскомментировать `<script src="net.js"></script>`
в конце `proto/index.html` и вернуть на экран `pvpScreen` кнопки создания и входа
по коду (разметка была в блоке `#pvpBox`, см. историю git).

## 14. Синхронный PvP на сервере (решённая архитектура)

Решение заказчика: **синхронный бой двух живых игроков, обсчёт боя и колоды — на сервере.**
Раздел описывает, как это устроено. Пока НЕ реализовано, это план.

Контекст площадки взят из ТЗ соседнего проекта «Оракул» (сервис в том же приложении):
WebView в МП «Клуб Друзей», МП передаёт данные пользователя при открытии, оплата только
через программу лояльности, состояние в продукте — на сервере, а не в localStorage.

**Вводные от заказчика:**
- ориентация экрана — как в прототипе (горизонтальная), портретной перерисовки не будет;
- **игра не шлёт уведомлений** — позвать игрока в бой нечем, оба должны быть в лобби;
- экономики сейчас нет;
- матчинг только обозначен, не продуман.

### 14.1 Лобби

Сервер держит присутствие: клиент шлёт «я здесь» раз в несколько секунд, молчание
дольше ~15 с — игрок пропадает из списка. В лобби показываются **все игроки, включая
себя** (своя строка помечена, без кнопки вызова). **Кодов комнат нет** — вызов по id
игрока из списка. Экраны «запрос на бой» и «ожидание второго игрока» из схемы (раздел 13)
нужны именно для этого.

Холодный старт остаётся риском: пока игроков мало, лобби будет пустым. Лечится пулом
или подбором — отложено вместе с матчингом.

### 14.2 Главный принцип

Клиент — **экран и джойстик**, а не движок. Он не считает бой: показывает присланный
сервером вид состояния и отправляет намерения:

```
{ seq: 12, t: "play", uid: 47 }   // сыграть карту из руки
{ seq: 13, t: "take", uid: 51 }   // взять новую карту над рукой
{ seq: 14, t: "end"  }            // конец хода
```

Всё остальное — следствия этого решения.

### 14.3 Защита от читеров

| Мера | Что закрывает |
|---|---|
| Сервер проверяет каждое действие: идёт ли бой, твой ли ход, не разыгрывается ли эффект, лежит ли `uid` в ТВОЕЙ руке, хватает ли энергии | Карты не из руки, игра без энергии и не в свой ход |
| **Туман войны:** про себя игрок получает всё, про соперника — только числа (HP, блок, сила, ловкость, энергия) и РАЗМЕРЫ стопок. Содержимое чужой руки и порядок любой колоды не уходят в браузер никогда | Подглядывание. Клиентский движок так не умеет в принципе — ему нужно всё состояние |
| Случайность только на сервере: тасовка, случайная карта для `copyHand`, позиция вставки `copyDeck`. Зерно пишется в запись матча, клиенту не отдаётся | Перекрутка тасовки до удобной |
| Числа карт берутся из серверной копии базы; `cards.js` на клиенте — только для отрисовки | Патч клиента «урон 6 → 60» |
| Возрастающий `seq` у каждого намерения, всё ≤ последнего применённого игнорируется | Двойная отправка и повтор пакета |
| Колода берётся из серверного хранилища, сервер сам проверяет 20 карт, ≤3 копий, наличие в коллекции | Нелегальные колоды и карты, которых нет |
| Подписанный id из WebView → сервер проверяет подпись → короткоживущий токен сессии | Подмена личности |
| Таймер хода на сервере, клиент его только рисует; истёк — сервер сам завершает ход | Затягивание и зависшие бои |
| Окно на переподключение, состояние матча живёт на сервере; несколько пропущенных ходов → техническое поражение | Выход при проигрыше; при этом честный обрыв не карается сразу |
| Ограничение частоты действий на соединение | Флуд и случайные циклы |

**Чего этим не закрыть** (честно, чтобы не было ложного ощущения безопасности):
- бот, играющий за человека — все его действия легальны, сервер их не отличит;
- договорные бои между двумя аккаунтами.

Обе проблемы становятся реальными только вместе с экономикой, а её пока нет.

### 14.4 Что это значит для кода

Главное препятствие — то же, что записано в разделе 3: **движок боя и интерфейс сплетены
в одном `<script>`**. Правила (`startTurn`, `resolveCard`, `applyDamage`, `checkWin`,
`finishTurn`, `drawCards`) перемешаны с `render()`, `logMsg`, `popup` и анимационными
паузами. Их надо вынести в модуль без DOM, общий для сервера и клиента;
`proto/proto-test.js` (71 проверка) прогоняется против него же и служит страховкой.

- `relay.js` из тупого релея становится сервером матчей;
- `proto/net.js` худеет: приём вида состояния и отправка намерений, расчёта не остаётся;
- приём с переворотом снимка («свои и чужие местами») переиспользуется — сервер так же
  готовит вид под каждого игрока;
- **бой с ботом остаётся на клиенте** как есть: там нечего защищать.

Транспорт: опрос раз в ~500 мс. Для пошаговой игры хватает и надёжнее в нестабильной сети
WebView. WebSocket даст мгновенность, но это отдельная сложность — начинаем с опроса.

### 14.5 Порядок работ

1. Вынести правила из `index.html` в модуль без DOM, прогнать `proto-test.js`.
2. Сервер: матчи, проверка действий, виды состояния, случайность, таймеры ходов.
3. Клиент PvP: рисует присланный вид, шлёт намерения.
4. Лобби с присутствием и вызовом по id.
5. Идентификация из МП, колоды и коллекция на сервере.
